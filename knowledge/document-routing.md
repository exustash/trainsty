## Where does a document belong?

> Read this before adding a document under `knowledge/`. **Deliberately not
> auto-loaded** — you know when you are filing a document, so this is a reference
> you consult, not a rule you could violate unknowingly. That is the same test
> `CLAUDE.md` applies to [index.md](index.md), which is the map.

Each folder keeps one job, so a document is findable by the question it answers
rather than by the feature that prompted it.

### The folders

| Folder | Owns | Not |
| --- | --- | --- |
| `architecture/` | System shape, module boundaries, the decisions behind them | A procedure |
| `conventions/` | **Standing rules for writing code**, per layer. Auto-loaded, because you can violate one without knowing it exists | A procedure you follow deliberately |
| `data/` | State: what exists, where it lives, and what may touch it. On this project that is mostly *what is deliberately not written down* | |
| `domains/` | The vocabulary and the model | |
| `playbooks/` | **A procedure you follow deliberately**, start to finish — integrating a Runner, recovering a stuck Lock | A rule |
| `product/` | The mirrored requirements note and the `FR`/`TS`/`Q` register | **Edits to the mirror** — see below |

**`conventions/` versus `playbooks/` is the auto-load test, not a topic test.**
Import what you can violate *without knowing*; reference what you look up once you
already have the question. A rule about how to write an SSE handler is a
convention. The steps for wiring a repository's Runner are a playbook.

### `product/` is two different things, and one of them is read-only

- **[local-ci-scheduler-requirements.md](product/local-ci-scheduler-requirements.md)
  is a byte-identical mirror** of `~/Obsidian/Notes/Inbox/local-ci scheduler.md`.
  An edit made here is a defect, not an update: change the vault, then re-copy.
  [product/decisions.md](product/decisions.md) → *Re-copying the mirror* has the
  command and the `cmp` that verifies it.
- **[decisions.md](product/decisions.md) is authored here** and is a **register,
  not a decision record** — one row per `FR` / `TS` / `Q` with the files that
  restate it. `RULES.md` §8.6 calls that last column the only thing that makes a
  sweep mechanical.

### Decisions get a decision record — and there are two

| Concern | Record |
| --- | --- |
| System shape, dependencies, platform, protocol choices | **ADR** — [architecture/adr.md](architecture/adr.md) |
| What is written outside memory, and what reads it back | **DDR** — [data/ddr.md](data/ddr.md) |

**And an SDR, since 2026-09-13.** `OD-1` — who may terminate a Job — was settled by
`specs/001-serialize-e2e-runs/spec.md`'s clarification round, and this file had already
said where the answer would go: **[security/sdr.md](security/sdr.md)**, not an ADR,
because filing a security decision among protocol choices buries it. **SDR-001** is
that record.

| Concern | Record |
| --- | --- |
| A security control, or anything that weakens one | **SDR** — [security/sdr.md](security/sdr.md) |

**No IDR either, and that one is not a gap:** there is no hosting to decide. A
locally installed binary has no infrastructure.

### The two that are not folders

- **[ERRORS.md](ERRORS.md)** — written **after** resolving something, in
  `RULES.md` §8.1's four-part shape. An **unfixed** finding cannot supply `Fix:` or
  `Prevention:`, so it is a task line, not an entry here. Neither is a failure mode
  the design merely anticipates — that belongs to the record that decided the
  mitigation.
- **`specs/**/tasks.md`** — work to be done, as lines. Generated by the Spec Kit
  commands in `.claude/skills/`.

### Filing one updates the registers

`RULES.md` §8.6: a document added, renamed or reclassified moves
[index.md](index.md). Then whichever decision record or register carried its
status — `architecture/adr.md`, `data/ddr.md`, or
[product/decisions.md](product/decisions.md)'s last column.

### Quick test

*Designing what the system should be* → `architecture/`. *Recording what we chose*
→ ADR or DDR. *Writing down a rule an agent could break unknowingly* →
`conventions/`. *Writing down a procedure someone follows on purpose* →
`playbooks/`. *A word that must mean one thing* → `domains/`. *What the
requirements note asked for* → `product/`, and only the register is writable.
